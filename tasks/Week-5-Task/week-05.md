## Goal for the Week

This is the **final week** of CHIP-Monks. Your focus is to try and get an **interactive CHIP-8 system running** using **Verilator**, a high-performance Verilog simulator that compiles your HDL into C++ instead of previous week's Python's `pygame` and Shell script route. You will write a C++ test harness that connects the Verilog design to a real emulator loop with keyboard input and dynamic graphics.

---

## Part A – Verilator Integration

Use Verilator to compile your Verilog modules (CPU + memory + display) into a C++ simulation model.

- Create a top-level Verilog module (`chip8_top.v`) that instantiates the CPU, memory, display, and other required modules
- Simulate using Verilator by compiling this module into a C++ class
- Write a `main.cpp` that:
    - Loads a ROM binary file
    - Drives clock/reset signals manually
    - Interfaces with keyboard input and updates the display framebuffer
- Use libraries like **SDL2** for graphics and keyboard input (if comfortable)

> [!TIP]
> Keep your simulation loop close to 60Hz (CHIP-8’s native speed) using a timer module(The timer module can very well be implemented in your CPU module too)!

---

## Part B – Real-Time GUI Shell (via C++)

Convert your Tcl-based dummy GUI into an actual interactive interface using C++ and Verilator.

- Use a C++ `main.cpp` file to:
    
    - Load the ROM 
        
    - Feed display updates from Verilog into a real GUI window
        
    - Forward keypresses from the user into Verilog input ports
        
- You may use any of the following:
    
    - `SDL2` for a graphical window
        
    - `raylib` for modern graphics and input
        
    - `ncurses` or ASCII printing for terminal-based output

> [!NOTE]  
> You are free to design your own GUI logic. You can borrow minimal frontend snippets from open-source projects, but do **not copy entire projects**. You must connect your own RTL backend.

### Final Expectations

- Top-level Verilog hierarchy (`chip8_top.v`)
- ROM load support
- Real-time input/output loop (60Hz)
- Minimal but complete playable interface (keyboard + display)

## Bonus: Future Implementation Ideas

Here are some optional paths for extending or hardening your project after this week.

### Make the design FPGA-friendly

- Add synchronous reset and avoid `initial` blocks
- Convert inferred memories to synthesized ones (e.g., use RAM IPs)
- Add a bus interface (wishbone, AXI-lite, etc.)

### Parameterize the design

- Make screen resolution, RAM size, etc., configurable with Verilog parameters

### Build peripheral wrappers

>[!NOTE]
> This section is slightly advanced stuff. But it's an idea that came across my mind :D so do check it out!

- Wrap display and input as AXI or APB peripherals
- Explore integrating your CHIP-8 as a peripheral inside an SoC
